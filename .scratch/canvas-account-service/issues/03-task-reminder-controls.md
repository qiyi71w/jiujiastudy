# 03 — 停止和恢复单项任务提醒

**What to build:** 学习者在 `/canvas tasks` 查看任务、已停止项，通过按钮确认停止或恢复提醒；截止变更或明确重新提交要求会解除手动停止并通知。

**Blocked by:** 02 — 在刷新日报中可靠呈现提交状态与部分失败

**Status:** resolved

**Guardrails:**
- 提醒意愿与 Canvas 已提交/豁免分开，学生不能在 Bot 授予学校豁免。原因可选，停止决定持久保存。
- 通过共享操作与结构化按钮实现，回调再次检查授权、任务归属、当前版本和有效性；状态更改本身不访问 Canvas。
- 已提交/豁免过滤优先；改期解除手动停止不等于把已提交任务改为未交。一般评分/批语不触发重新提交。

- [x] 真实 Telegram 任务列表、已停止列表和确认按钮可用，取消不改状态，停止/恢复后 report 立即体现，重启仍保留。
- [x] 停止原因可选；刷新后截止变更或明确重交要求解除停止并通知一次，已提交仅改期仍不催交。
- [x] 重复、过期、伪造和跨账号回调不重复修改或泄露数据；并发任务决定不互相覆盖。
- [x] 更新完整帮助；用离线状态转移测试和真实长列表/按钮观察证明，不断言文案。05 验证关闭时任务操作，07/09验证双端共享。

原生要求：Telegram 测试 Bot；提醒状态转移由受控 Canvas 场景证明。覆盖 V06 的单端路径。

**Source:** [Canvas 多账号每日提醒与双端私信服务](../spec.md)。本票列出的验收是完成门槛；模拟覆盖与真实平台验收分别记录，缺少必需原生条件时不得以模拟结果关闭任务。

# 06 — 管理自动加入的课程与退出课程

**What to build:** `/canvas courses` 展示监控和已停止课程，用户可停止或重新加入；自动发现尊重停止决定，结束或失权课程不再依据旧任务催交。

**Blocked by:** 05 — 安全开启或关闭整个账号服务

**Status:** ready-for-agent

**Guardrails:**
- 新课继续按现有筛选自动加入并提示一次；不增加确认入课流程。主动停止的课程持久保存，扫描不会自动加回。
- 开启时重新加入即采集，当前采集未涵盖则补采；关闭时只改选择，不请求/发现课程。
- 课程生命周期与用户停止分开；暂时网络故障不能当成结束或失权。按钮使用共享操作，不在渠道文案中实现规则。

- [ ] 真实 Telegram 列表支持停止/重新加入，重启保留；停止课后续不拉任务、不自动恢复。
- [ ] 新课首次自动采集并提示，定时发现发送所有端、手动仅发起端；重复扫描不重复新课通知。（单端离线已验，双端待 07/09）
- [x] 关闭时只保存选择，再 on 按保存范围采集；开启时重新加入及时反映新数据，并发采集中加入不遗漏、不并发损坏快照。（受控 HTTPS MockCanvas）
- [x] 明确结束或失权首次进入该状态时提示确认，保留课程与历史且不标完成，但旧任务立即退出催交区；临时 5xx 只标过期数据，不进入退出状态或触发退出确认。（受控 HTTPS MockCanvas）
- [ ] 伪造/失效按钮被拒绝，help 更新；复用 CourseListRefresh/PartialCollect 类型场景并验收真实课程按钮。

原生要求：Telegram 测试 Bot，课程变更与故障用 MockCanvas。覆盖 V04/V08/V11，双端归07/09。

# Canvas 多账号每日提醒与双端私信服务

Status: ready-for-agent

## Problem Statement

学习者目前主要通过本地 Agent Skill 主动查看 Canvas，无法在电脑和 AI 助手未运行时稳定收到每日作业提醒。学习者需要知道哪些作业尚未提交、何时截止、是否改期，以及新课程是否已自动纳入监控，而不是把“做完了”“已提交”和学校给予的豁免混为一谈。

多位学习者希望由可信托管管理员在服务器上运行此服务，分别通过自己的 Telegram 或 Discord 私信接收消息及主动更新。各账号的课程、凭据、设置和 AI 输入必须隔离。Canvas 地址必须明确配置；不能携带凭据猜测站点。自动访问应保持低频，且不能把低频或随机扫描时间当成符合学校政策的保证。

## Solution

保留本地 Skill，新增服务器模式：每个 Canvas 账号独立容器，绑定专属 Telegram Bot、专属 Discord Bot，或同时绑定两端；只允许管理员预设的同一学习者通过对应私信访问。

账号服务开启时，每天在使用者设置的基准时间后随机延迟 0–15 分钟扫描一次，检查监控课程中的任务及提交状态，生成每日固定日报并发送到所有启用端。主动命令支持查看快照、即时刷新、即时 AI 解读、开启或关闭账号服务、选择课程和停止或恢复任务提醒。

基础日报无需 AI。管理员可配置模型 API 和账号每日调用上限；学习者分别控制 AI 开关、自动摘要及公告解读授权。AI 不决定提交状态，也不覆盖 Canvas 正式截止时间。失败时保留可用的规则日报，并明确数据时间和失败范围。

## User Stories

1. As a 学习者, I want a 每天自动发送的作业日报, so that 我不必启动本地电脑或 AI 助手，也能看到未来七天待交、逾期未交、新增改期、最近已提交及日期不明的任务，并在无待交时收到确认。
2. As a 学习者, I want a 依据 Canvas 记录判断提交与豁免的提醒服务, so that 已提交未评分的作业不再被催交，而线下或未知状态不会被武断认定为未交或完成。
3. As a 学习者, I want a 自动加入新课程的监控清单及课程管理入口, so that 新课任务不会因忘记手动添加而遗漏，我也能停止不需要的课程监控并在需要时重新加入。
4. As a 学习者, I want a 可确认停止和恢复单项任务提醒的入口, so that 我能处理线下任务等特殊情况，而不改变 Canvas 的提交或豁免状态，并在任务重要变化时重新得到提醒。
5. As a 学习者, I want a Telegram、Discord 任一或双端的授权私信入口, so that 我能在常用平台使用同一账号的课程设置、提醒状态及 AI 额度，且私人命令只在发起端回复。
6. As a 学习者, I want a 完整帮助、状态、快照日报和即时刷新命令, so that 我能了解所有操作、数据新鲜度和下次扫描时间，并在需要时主动获取最新 Canvas 数据。
7. As a 学习者, I want a 账号级 on/off 开关及可调整的扫描时间与时区, so that 我能控制服务何时工作，关闭后仍查看旧数据和管理设置，恢复时立即更新。
8. As a 学习者, I want a 默认关闭且可单独授权内容的 AI 解读能力, so that 我能按需即时采集后提问或开启每日摘要，而不把未授权材料交给模型，也不让 AI 故障影响基本提醒。
9. As a 可信托管管理员, I want a 面向 2–10 个 Canvas 账号的独立部署、显式凭据绑定和受限私信授权, so that 不同学习者的数据不会串号，接收身份、API 密钥及费用上限由我管理。
10. As a 学习者和可信托管管理员, I want a 可恢复、能说明部分失败且只保留必要数据的服务, so that 重启、渠道故障或采集失败不会造成静默漏报、错误完成判断或无限积累课程历史。
11. As a 本地 Skill 使用者, I want a 保持可用的现有本地流程, so that 服务端功能不会强制改变我的本地配置、课程处理方式或人工确认写入流程。

## Implementation Decisions

### 账号隔离与共享逻辑

- 面向 2–10 个账号；管理员可信，学习者之间隔离，不承诺对服务器管理员保密。
- 每账号独立容器、持久数据和秘密，共用镜像与代码；受限用户运行，仅挂载自身数据，不暴露其他账号目录或容器管理权限。资源占用通过实际运行测量，不预先承诺容量数字。
- 单个账号容器可同时运行两种渠道；共用账号操作、采集协调、规则日报、计划扫描、任务提醒状态、AI 授权和额度。渠道适配不复制业务规则。
- 复用已有配置、Canvas 采集、deadline 计算和规则输出能力，必要时从 CLI 调用层提取共享逻辑；沿用现有配置体系，不增加同一账号的第二份事实源。
- 本地与服务端复用现有课程发现和筛选规则，符合条件的新课程自动纳入监控；服务端额外持久化用户主动停止的课程，避免再次扫描时自动加回。服务端即时采集绕过普通缓存，本地普通缓存语义保留。
- 现有学习完成记录不等同于 Canvas 已提交；普通备注也不能代替手动停止提醒状态。

### 端点与凭据

- Canvas 必须显式配置完整 HTTPS 地址；缺失时阻止采集，不探测候选站点。首次 token 验证只访问指定站点，更换站点要求明确重新绑定凭据。
- 每次携带凭据的请求检查指定 origin，涵盖分页链接和重定向；跨 origin 或降级目标不得接收凭据。
- AI 端点同样显式配置；按配置服务验证 OpenAI-compatible 接入，密钥不随跨 origin 跳转发送。
- 凭据通过受限秘密文件或部署秘密注入，不进入仓库、日志、配置示例和聊天；包含 token 的请求 URL 也需脱敏。
- 服务端只读 Canvas，不提供发帖、发信和交作业操作。本地既有写入功能继续使用原人工确认边界。

### 渠道与权限

- 每个启用渠道绑定独立账号专属 Bot；管理员预设授权使用者，Telegram 校验用户及私聊，Discord 仅支持授权用户与 Bot 的私信。
- 首次联系不能让任意先到用户认领 Bot；两端用户身份由管理员确认属于同一学习者，不按用户名自动关联。
- 管理员负责更换接收身份、Bot 凭据和绑定；用户不能通过命令指定其他账号、任意路径、站点、收件人或频道。
- 群聊、Discord 服务器频道、陌生用户、伪造和过期按钮均不得读写账号数据。Discord 私信失败不能回退到服务器频道。
- Telegram 采用 long polling；Discord 优先采用出站 Gateway 和原生私信命令交互，实现时核对官方安装、权限与交互要求，不要求为了接收命令开放公网入站端口。

### 课程与任务

- 每次实际采集更新可见课程列表，按现有课程筛选规则自动将符合条件的新课加入监控，并读取其必要任务数据；不默认下载课件或采集无关站内信。
- 新课程自动加入后首次提示一次，随后作为监控课程展示。初次任务快照作为基线，不把全部已有作业标为新增。
- 授权使用者通过课程按钮停止监控或重新加入；主动停止的课程不被后续扫描自动加回。服务开启时新课自动加入或手动重新加入均立即采集该课，关闭时仅保存选择且不发现新课。若进行中的采集未覆盖新增课程，需补采而不能遗漏。
- 定时发现的新课随日报发往所有启用端；手动发现仅回复命令发起端。
- 课程明确结束或失去访问权限时提示确认并暂停旧数据催交，不删除任务或认定完成；短暂网络故障不触发课程退出。
- Canvas 确认已提交或豁免后不再催交；尚未评分不是未交，有分数也不独立证明已提交。线下和无法确认的状态显示需确认。
- 使用适用于该学习者的截止时间；组作业、测验、个别延期和重新提交按实际 Canvas 数据语义处理，证据不足保持未知。一般评分或批语变化不能推断成要求重新提交。
- 任务按钮支持查看状态、确认停止或恢复提醒、可选停止原因及已停止列表；学生不能通过 Bot 授予 Canvas 豁免。
- 截止日期变化或 Canvas 明确要求重新提交时解除手动停止并通知；已提交任务只改期不能变成未提交，提交及豁免过滤仍优先。

### 计划扫描、状态与恢复

- 每账号每天自动扫描一次，使用使用者设置的基准时间、IANA 时区及独立生成的 0–15 分钟延迟；计划时刻持久化，重启不重新抽取。
- 账号计划日与执行记录防止夏令时、午夜随机延迟、重启或时间/时区修改引发重复扫描。已执行的计划日不因改设置再执行。
- 截止时间按课程时区语义及真实时刻判断，不能依赖服务器默认时区；状态入口显示实际计划时刻与最近采集完整性。
- 恢复运行只补当天遗漏日报，不追发多日历史；扫描与消息投递独立记账，渠道重试不重新访问 Canvas。
- 手动刷新不设应用层冷却，仍遵守 Canvas 服务端限流。同账号复用适用的进行中采集，避免重复请求与并发写状态；不同账号不互相阻塞。
- 共享设置更新串行落盘，按钮动作重新检查授权与最新状态。手动快照查看、刷新或 AI 调用不消耗定时日报投递记录。
- 部分失败保留上一成功数据的新鲜度，成功课程仍更新；旧数据明确标时，不把缺失误判成删除或完成。

### 账号服务开关

- `/canvas off` 持久化关闭账号服务，两端共享；停止自动扫描、自动日报、新的手动采集与 AI 请求。Bot 仍在线，保留数据和设置。
- 关闭时允许 help、status、旧快照 report、课程和任务管理及设置修改；这些操作不访问 Canvas 或模型。
- 正在进行的外部请求无法保证撤回；返回后停止分页、后续采集、AI 和业务结果发送，不以取消任务的部分快照覆盖成功快照。已发送的消息不能声称可撤回。
- 关闭后迅速开启不能让旧任务恢复推送；旧任务失效状态必须保留。
- `/canvas on` 从关闭转开启时立即采集并恢复每日计划；已开启时重复执行不采集，重复 off 同样无额外副作用。
- on 触发的采集：若当天尚未自动扫描，则计入当天任务并向所有启用端交付日报；当天已执行则只回复命令发起端。关闭期间不积压多日待补日报。

### 命令与设置入口

| 命令 | 用户可观察行为 |
| --- | --- |
| `/canvas help` | 显示全部支持命令、参数、用途及可用条件；完整列出 help、status、report、refresh、ai、on、off、courses、tasks，提供带问题的 AI 示例；关闭状态也可用，AI 未启用时不隐藏命令；不触发采集或模型调用 |
| `/canvas status` | 显示服务状态、最近采集时间和完整性、实际下次扫描时间、渠道与 AI 状态，不主动采集 |
| `/canvas report` | 返回当前快照日报并注明数据时间；无快照时明确说明 |
| `/canvas refresh` | 立即采集并发送规则日报 |
| `/canvas ai [问题]` | 立即采集，完整成功且符合授权与额度条件后执行摘要或单次问题分析 |
| `/canvas on`、`/canvas off` | 按账号服务开关规则执行 |
| `/canvas courses` | 查看自动纳入的监控课程及已停止监控课程，通过按钮停止监控或重新加入 |
| `/canvas tasks` | 查看任务及状态，通过按钮确认停止或恢复提醒，查看已停止项 |

- 两端使用相同业务语义，具体命令注册遵循平台能力；新增命令必须同步进入完整帮助。
- help/status 提供私信设置面板入口，用户调整基准时间、显示时区、AI 开关、自动摘要和公告授权；管理员控制端点、密钥和额度，用户不能提高额度。
- 及时确认命令接收，长任务完成后回复；消息按平台长度分段、正确转义，课程内容不得引发额外 mention 或伪装交互控件。

### 日报与双端投递

- 每日固定日报包含未来七天待交、逾期未交、新增和改期、最近已提交、新课程、日期不明任务、来源链接、数据时间及失败范围；无待交仍发送简短确认。
- 提交变化作为新变化只展示一次；仍未交的临期任务可继续出现在日报。事实字段由程序生成。
- 日报及自动 AI 摘要生成一次，向所有启用端分别投递，独立记录成功和失败，只重试失败端；单端故障不阻断另一端，也不重做采集或 AI。
- 主动命令只回复命令发起端；on 触发当天补日报是明确的双端发送例外。
- 不完整日报点名失败课程并区分新旧数据，不把采集失败报成无待交。必要失败与待投递状态持久化，日志不记录正文或秘密。
- 网络超时可能产生平台已接收但回执未知；按平台能力处理，不承诺跨平台严格 exactly-once，也不无界重试。

### AI 授权、额度与失败

- AI 默认关闭，配置 API 不自动开启每日解读；手动 AI 和每日自动摘要分别控制。
- 每账号每日次数上限由管理员配置、两端合计；并发预留与记账不能突破上限，可能收费的失败调用不能通过重试绕过限额。
- 即时 AI 请求必须先采集；部分采集失败时提供规则日报/失败说明，不调用模型。自动 AI 使用当次完整计划扫描结果，不额外扫描。
- 默认只发送必要任务信息，公告正文须独立授权；不发送凭据、个人资料、成绩、站内信、课件或其他账号的数据。
- 单次分析只处理授权数据；不联网、不调用工具、不保留多轮历史、不跨账号共享 AI 缓存。课程内容仅是数据，不能驱动服务操作。
- 日期、作业名称、提交状态和链接由程序固定呈现；AI 内容单独展示，公告提取日期附来源、标待确认，不覆盖 Canvas 正式时间。
- AI 关闭、额度不足、超时或错误响应不影响规则日报；清楚报告限制或失败，不伪造分析结果。

### 持久化与交付

- 保留账号配置、绑定身份、服务状态、每日计划及执行记录、课程发现/监控状态与用户主动停止记录、任务提醒决定、当前与上一成功快照、逐课程新鲜度、必要变化及逐端投递记录、AI 授权和额度。
- 仅保留运行必需数据；未投递变化不能因手动刷新覆盖快照而消失，清理不能删除有效用户决定。平台消息和模型供应商留存不受本地清理控制。
- 凭据轮换或迁移接收身份不能把旧身份待投递私人问答转给新身份。
- 交付镜像、账号独立部署配置、秘密注入、启动校验、重启恢复及操作说明；更新本地与服务端使用文档，解释快照查看和即时采集的区别。
- 按共享账号基础、核心课程/任务/调度、渠道与 AI 适配、端到端部署顺序集成；所有部分属于本规格完整范围。

## Testing Decisions

### 测试原则与现有依据

- 测试用户和外部服务可观察到的权限、请求、状态转换、消息内容类别、投递对象及持久恢复；不测试源码文本、内部字段搬运、固定文案或单纯 mock 回声。
- 沿用现有标准库 unittest、临时 FakeHome、回环地址 MockCanvas、固定时间和网络隔离的测试方式。普通离线测试不得访问真实 Canvas、读取用户真实 token 或触发付费服务。
- 现有 PartialCollect 场景已通过真实本地 HTTP 故障验证失败课程保留、其他课程更新及 complete 状态；扩展这一边界覆盖不完整日报和 AI 禁止调用。
- 现有 CourseListRefresh 场景覆盖新课自动出现、退课和课程状态；沿用此行为，扩展服务端自动采集与通知、用户停止监控后不被再次加入以及手动重新加入的测试。
- 现有 RelAcrossZones 场景通过固定时钟检验课程与用户日期、剩余时间和逾期；沿用该时间入口覆盖计划扫描、时区、夏令时和重启。
- 现有隔离 CLI/JSON 场景和跨地区 fixture 作为本地回归依据；不为服务器需求机械重录所有输出快照。
- 新服务通过公开命令处理与可观察持久状态验证账号操作，通过本地受控 HTTP 接收端验证 Canvas/AI 请求及渠道投递边界。无需额外公开测试专用产品 API。

### 验收结果

| 编号 | 必须观察到的结果 |
| --- | --- |
| V01 | 两账号凭据与数据隔离，A 的命令和按钮无法访问 B；真实容器仅挂载自身数据 |
| V02 | 陌生用户、群聊、Discord 服务器频道及失效/伪造按钮无法读取或修改课程信息 |
| V03 | Canvas/AI 的跨 origin、降级或缺失地址不会导致秘密外发；日志和消息不含秘密 |
| V04 | 符合筛选规则的新课自动加入并采集，首次通知后不重复；主动停止监控后后续扫描不自动加回，可手动重新加入；关闭时仅保存选择且不访问 Canvas |
| V05 | 已提交未评分不催交；仅有分数不误判；豁免免催交，线下未知显示需确认 |
| V06 | 手动停止和恢复双端共享，改期或确切重新提交要求解除停止；已提交改期不变成未交 |
| V07 | 重启保留随机计划，修改时区、夏令时及跨午夜不重复扫描；恢复只补当天，无待交仍发日报 |
| V08 | 两端并发 refresh/ai 复用进行中采集，新增监控课程不遗漏，共享设置不会互相覆盖 |
| V09 | 采集或 AI 期间 off 后不继续外部步骤或业务推送，保留成功快照；快速 off/on 不复活旧任务 |
| V10 | on 立即采集并按当天是否完成分流投递；重复 on 不采集，关闭仍可帮助、查看快照及管理设置 |
| V11 | 部分失败日报明确失败范围和新旧数据，不误报删除/完成；模型调用次数为零 |
| V12 | 日报单端发送失败只重试失败端，另一端正常；命令只回复发起端，Discord 私信失败不公开回退 |
| V13 | AI 关闭、额度耗尽、超时和错误响应不阻断规则日报；双端自动摘要仅生成一次 |
| V14 | 受控 API 接收端观察不到未授权公告、其他账号数据、成绩、站内信、课件及秘密；恶意课程文本不能触发工具行为 |
| V15 | AI 跨端并发仍受账号每日额度约束，程序事实与 AI 段落可区分，不保留多轮历史 |
| V16 | 最小保留和清理不丢失有效用户设置、未投递变化及逐端投递记录 |
| V17 | 本地 collect、radar、study 及原人工确认写入流程可用；服务器不扩大 Canvas 写权限 |
| V18 | 两端 help 展示全部命令、参数与用途；关闭或 AI 未启用时仍完整可见并说明限制；不会调用 Canvas/AI |

### 离线覆盖与真实验收

- 本地 fixture 覆盖采集成功/失败、限流、跨 origin 请求、提交边界、可控时钟、并发取消、AI 输入、额度和投递错误。测试网络防护保留，生产 HTTPS 限制不能为了本地测试而削弱。
- 真实 Telegram 和 Discord 测试 Bot 必须验证私信命令、按钮、授权与未授权身份、消息分段及双端行为；模拟发送器不能代替原生平台验收。
- 至少两个独立账号容器验证隔离、重启、计划持久化和故障互不阻塞；测量空闲及采集时的资源占用。
- 本地受控模型 API 可证明请求过滤、次数与回退；只有配置服务的真实调用才能证明供应商兼容。真实付费调用需要明确授权，缺少凭据时说明尚未完成的外部验收，不能声称已上线。
- 真实 Canvas 验收使用被授权账号并遵守学校政策；fixture 不能证明学校所有作业类型及个别延期字段均符合假设。
- 主实施者在集成后运行聚焦检查及按共享边界影响面选择的现有回归，不在每次局部编辑时重复运行全套。

## Out of Scope

- 自动提交作业、发帖、发站内信或修改 Canvas 学校侧豁免。
- 全天通用 agent、模型工具执行、联网研究或持续多轮聊天。
- 高频后台轮询、实时事件订阅和额外自动加急扫描；每天扫描之后的新变化可能到次日或主动刷新才发现。
- 群聊和 Discord 服务器频道投递、亲友共享访问、自助更换绑定、任意收件人转发。
- 对可信托管管理员保密的端到端托管模式，或公开大规模多租户服务。
- 课件下载与课件 AI 处理、长期历史日报查询仓库、自动删除聊天平台和模型供应商的留存。
- 用随机时间规避学校监控，或保证某种调用频率天然合规。
- 以 AI 猜测覆盖 Canvas 提交状态或正式截止时间。
